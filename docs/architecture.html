A small maintained interface

Keep parser details and native globals behind the core. Both operations use explicit, versioned input and immutable results.

Completion

complete(document, cursor, profile, schema?) → suggestions

Works on unfinished SQL. Returns candidate text, kind/detail, and an exact replacement span in the original document.

Diagnostics

diagnose(document, profile, scriptMode) → diagnosticResult

Runs qualified syntax checks and selected lint rules. Reports syntax errors, unsupported coverage, and tool failures distinctly.

Shared data

Document · Span · Profile · SchemaSnapshot · Diagnostic

One range convention, stable codes, and explicit conversions for parser bytes and editor positions. Snapshots contain metadata, with credentials owned by consumers.

Parser implementation

qualified backend behind the diagnostic interface

The current native-worker checkpoint can be reused. Each supported CUBRID build needs qualification. The first target remains the pinned 11.5 build.

Python is a practical first implementation because the existing completion code already uses it. The parser worker remains internal. A future runtime change can preserve the LSP and CLI contracts, while library consumers would need a migration.

A shared engine can use tolerant analysis for completion and strict parsing for validation. A parser rejection during typing must still allow useful suggestions. Additional semantic/style rules can grow behind the diagnostic interface with explicit coverage.
