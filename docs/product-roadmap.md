# 개발·제품 로드맵

**한국어** | [English](product-roadmap.en.md) · [문서 목차](README.md)

개발 순서는 **Python PoC → 동작 검증·계약 안정화 → Rust 점진 전환**입니다.
공통 엔진과 소비 제품은 독립적으로 배포합니다.
이 문서는 목표를 설명하며 배포 날짜나 구현 완료를 약속하지 않습니다.

## 1. Python PoC로 흐름부터 확인

`cubrid_language` 패키지에서 완성·원문 범위·스키마·진단 값을 검증합니다.
미완성 SQL도 완성하고, 엄격한 문법 검사는 별도 CUBRID 네이티브 워커를 사용합니다.
파일·표준 입력을 검사하는 CLI와 stdio LSP 어댑터로 같은 결과를 제공합니다.

첫 파서 대상은 Linux x86-64의 `cubrid-11.5.0.2704-cc94778` 프로파일입니다.
현재 소스는 제한된 v4 문법 검사, SHOW·힌트 작성 지원, 확대된 CSQL 명령 텍스트 검사를 제공합니다.
파서 부재·미지원 구문을 문법 성공으로 취급하지 않습니다. [설치](install.md)와 [지원 범위](coverage.md)를 확인합니다.
구현은 공개 main에 통합했습니다. 설치 안내에서 현재 v4 검사와 과거 v3 배포 환경 검증을 구분합니다.

코어·CLI는 Python 3.10 이상에서 필수 Python 런타임 의존성 없이 동작합니다.
LSP 의존성은 선택적으로 설치하며 네이티브 런타임은 별도로 검증합니다.
PoC 완료와 운영 배포 검증 완료를 구분합니다.

## 2. 공통 검증 기준을 고정

Rust 교체와 소비자 연동을 평가할 수 있도록 다음 결과를 공통 코퍼스에 남깁니다.

- 정상·오류·미완성 SQL·CSQL의 완성 후보와 순서.
- 인용 식별자·소유자·별칭·테이블·컬럼의 대체 범위.
- 한글·이모지·CRLF 주변의 코드 포인트·UTF-16 위치 변환.
- 문법 오류·미지원·도구 실패의 진단 코드와 상태.
- CLI JSON·종료 코드와 LSP 문서 변경·취소·오래된 진단 제거.
- 파서 빌드 식별값, 지원 문법 범위, SQL 미실행·DB 미접속 근거.

현재 터미널에서 가져오는 어휘에는 11.4 매뉴얼 출처가 포함됩니다.
엄격한 11.5 파서 검증과 구분하고, 버전별 출처·지원 범위를 명시합니다.

## 3. 검증한 모듈부터 Rust로 교체

전체를 한 번에 다시 쓰는 대신, 경계가 정해진 모듈을 선택해 Rust로 옮깁니다.
Python 구현과 같은 입력을 비교하고 해당 모듈의 계약을 만족한 뒤 교체합니다.
전환 중에는 Python·Rust 구현이 함께 존재할 수 있습니다.

교체 순서는 PoC 결과와 의존 관계를 보고 정합니다.
공통 값·완성·검증 어댑터·CLI·LSP 등 각 경계의 결과를 따로 검증합니다.
직접 Python import를 쓰는 제품의 바인딩·호환 계층도 해당 단계의 완료 조건입니다.
특정 FFI 기술이나 새 Rust SQL 문법을 미리 확정하지 않습니다.

Rust로 바뀌어도 CLI·LSP 프로토콜과 관찰 가능한 결과를 유지하는 것이 목표입니다.
언어 교체만으로 성능·호환성이 개선됐다고 주장하지 않고 실제 검증 결과를 기록합니다.

## 4. 별도 소비 제품으로 확장

검증된 Python 인터페이스부터 사용할 수 있으며 모든 모듈의 Rust 전환을 기다릴 필요는 없습니다.

| 제품 | 현재 기능 또는 예정 연동 |
| --- | --- |
| csql-future | 공통 완성 라이브러리 전환 예정. 현재 자체 완성·히스토리·메뉴·접속·카탈로그 조회를 유지 |
| [VS Code 확장](https://github.com/vimkim/cubrid-vscode) 알파 | 전용 `cubrid` 언어 ID, LSP 완성·진단, 구문 강조, 들여쓰기, 선택적 `.sql` 연결 |
| [Neovim 플러그인](https://github.com/vimkim/cubrid.nvim) 알파 | filetype·내장 LSP, 완성·진단, 구문 강조·들여쓰기·스냅샷 재로드 |
| AI·CI 도구 | 구조화된 린트 결과와 실패 상태를 작업 흐름에 연결 |

터미널 전환은 후보·Unicode 편집·메타데이터의 동등성과 기존 PTY 검사를 통과해야 합니다.
편집기 스키마 완성은 오프라인 메타데이터 스냅샷을 사용합니다. 공통 [스키마 exporter](schema-export.md)로 CSQL에서 명시적으로 수집할 수 있습니다.
접속 선택과 새로고침 일정은 소비 제품이 소유합니다.
접속 입력을 제안할지는 편집기가 정하며 코어는 자동으로 시작하지 않습니다.

## 5. 이후 언어 지원 확대

- **포매팅:** CUBRID SQL 포매터를 개발하고 VS Code·Neovim의 포매팅 동작과 연결합니다.
- **구문 강조:** 초기 편집기 어휘 규칙 이후 Tree-sitter 도입을 검토합니다.
- **의미·스타일 린트:** 초기 문법 진단과 구분된 규칙·코드·수정 계약을 정의합니다.
- **완성 범위:** CTE·파생 테이블·상관 쿼리·동의어의 결과 추론을 확대합니다.
- **객체 설명:** 2026-10-29에 수용한 SHOW COLUMNS·DESCRIBE·DESC·클래스 설명용 EXPLAIN 제외를 유지하고 별도 parser-only backend를 검증합니다. 원래 객체 설명 검증 기준은 통과하지 않았습니다.
- **문법·플랫폼:** PL/CSQL, 다른 11.5 빌드·11.4, 추가 운영체제를 각각 검증합니다.

포매팅·의미·스타일 린트는 아직 제공하지 않습니다.
지금 사용할 수 있는 터미널 기능은 [csql-future 저장소](https://github.com/vimkim/csql-future)에 있습니다.
