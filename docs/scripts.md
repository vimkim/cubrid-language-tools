# 오프라인 CSQL 배치 스크립트

**한국어** | [English](scripts.en.md)

공유 `Validator`는 SQL이나 명령을 실행하지 않고 CSQL 배치 문서를 검사합니다.
CLI와 LSP는 같은 분류와 진단을 사용합니다.
[CLI 설정](lint-cli.md) 또는 [LSP 설정](lsp.md)에서 `scriptMode: csql`을 선택합니다.
`.csql` 파일은 기본적으로 CSQL 모드입니다.
다른 파일·표준 입력·제목 없는 문서는 명시적인 설정이 없으면 SQL 모드입니다.

## 검증한 명령

지원 범위는 다음 완전한 명령 줄입니다.

```text
;help
;exit
;autocommit on
;autocommit off
;commit
;rollback
;time on
;time off
;line-output on
;line-output off
```

이 형식의 명령 이름과 인수는 대소문자를 구분하지 않습니다.
명령은 문자열·주석·따옴표 식별자 밖의 첫 번째 열에서 시작해야 합니다.
줄 끝은 LF·CRLF 또는 최종 EOF일 수 있습니다.
autocommit·time·line-output과 인수 사이는 하나 이상의 ASCII 공백·탭으로 구분합니다.
명령 뒤의 ASCII 공백·탭도 허용합니다.
들여쓰기·축약형·추가 인수·비 ASCII 후행 공백·추가 세미콜론은 미지원입니다.
실제 인터프리터보다 좁은 범위이며 인수 없는 time·line-output 조회도 미지원입니다. 잘못된 인수는 문법 오류가 아닌 미지원으로 보고합니다.

검사기는 문서 전체를 검사합니다.
허용한 exit 명령 뒤도 계속 검사하며 세션이나 트랜잭션 상태를 바꾸지 않습니다. commit·rollback 허용은 텍스트 형식만 검사한다는 뜻입니다.
명령만 있는 문서·빈 문서·미지원 구문만 있는 문서도 검증한 프로파일과 사용 가능한 워커가 필요합니다.
알 수 없는 프로파일은 `CUBRID-U1001`, 없는 워커나 런타임 자산은 도구 오류입니다.

include·셸 명령·`!` 명령·버퍼 제어·PL/CSQL은 미지원입니다.
검사기는 include 대상 읽기·셸 시작·자격 증명 요청·데이터베이스 연결을 하지 않습니다.
SQL 모드는 CSQL 명령을 허용하지 않고 원문 전체를 검증한 SQL 워커에 전달합니다.

## 경계와 보수적인 복구

여러 줄 어휘 블록 안의 명령 줄은 SQL 내용으로 남습니다.
스캐너는 작은따옴표·큰따옴표·백틱·대괄호·일반 주석을 구분합니다.
중복 구분자와 해당 프로파일의 작은따옴표 문자열 역슬래시 이스케이프도 반영합니다.
이 블록 안의 세미콜론은 SQL 문장을 끝내지 않습니다.
LF만 다음 배치 줄을 시작합니다. CRLF는 원문 코드 포인트 두 개입니다.

완료된 SQL 문장 앞뒤에는 명령 줄을 둘 수 있습니다.

```sql
SELECT '가😀;';
;help
SELECT 2
```

최종 SQL 문장은 네이티브 파서가 허용하면 세미콜론 없이도 검사합니다.
SQL 조각은 주석과 줄 끝을 포함한 원문을 그대로 유지합니다.
네이티브 문장 범위에는 앞선 공백·주석이 포함될 수 있습니다.

미완료 SQL 안의 명령은 보수적으로 처리합니다.

```text
SELECT
;help
1;
```

실제 인터프리터는 정보 명령을 처리하면서 SQL 버퍼를 유지할 수 있습니다.
현재 검사기는 미완료 문장부터 문서 끝까지를 하나의 미지원 영역으로 남깁니다.
조각을 따로 파싱해서 문서 전체의 문법 오류처럼 보고하지 않습니다.
괄호가 열린 SQL이나 버퍼 효과를 모르는 미지원 명령에도 같은 제한을 적용합니다.
이 제한을 피하려면 세미콜론으로 끝낸 SQL 문장 사이에 명령을 둡니다.

프로시저 영역도 EOF까지 불투명하게 유지합니다.
시작 형식은 `CREATE [OR REPLACE] PROCEDURE`·`FUNCTION`·`PACKAGE` 또는 `BEGIN`·`DECLARE`입니다.
내부 세미콜론 뒤 SQL을 별도의 성공한 검사로 노출하지 않습니다.
프로시저의 겉보기 끝 이후에도 복구를 시도하지 않습니다.
프로시저 안의 미종료 따옴표·주석은 미지원 진단과 함께 문법 진단도 유지합니다.

## 원문 오프셋과 결과

라이브러리 범위는 0부터 시작하는 유니코드 코드 포인트이며 끝 오프셋은 제외합니다.
분류기는 유니코드·대소문자·공백·줄바꿈을 정규화하지 않습니다.
반환하는 불변 조각의 범위는 원문을 가리킵니다.

```python
from cubrid_language.scripts import classify

text = ";help\r\nSELECT '가😀;';"
for part in classify(text):
    original_slice = text[part.span.start:part.span.end]
    print(part.kind, part.span, original_slice)
```

조각 종류는 `sql`·`command`·`unsupported`입니다.
`lexical_error`는 미종료 SQL 어휘 블록을 나타내며 문법 통과를 뜻하지 않습니다.
분류는 순수 함수이며 파일시스템·프로세스·데이터베이스 작업을 하지 않습니다.
엄격한 검사는 설정한 [Validator](lint-cli.md#python-인터페이스)를 사용합니다.

Validator는 각 SQL 조각의 진단 범위를 원문 문서 오프셋으로 옮깁니다.
문장 정밀도를 유지하며 토큰 정밀도를 추정하지 않습니다.
CLI JSON은 코드 포인트 범위를, 사람이 읽는 CLI 출력은 1부터 시작하는 코드 포인트 열을 사용합니다.
LSP는 같은 범위를 UTF-16 프로토콜 범위로 바꿉니다.

문법 진단과 미지원 진단은 함께 존재할 수 있습니다.
상태 우선순위는 `tool-error` → `syntax-error` → `unsupported` → `valid`입니다.
나중 워커 실패가 앞선 진단이나 이후 분류한 미지원 영역을 지우지 않습니다.
선택한 프로파일에서 모든 영역을 검사할 수 있어야 지원 범위가 완전합니다.
문서 진단 수 제한은 명령 경계에서도 초기화하지 않습니다.
제한을 넘으면 결과가 잘렸다는 메시지와 함께 도구 오류를 반환합니다.

## 검증 범위와 소스 경계

스크립트 분류는 네이티브 문법 지원 범위를 넓히지 않습니다.
정확한 11.5 프로파일의 SQL 범위는 일치하는 네이티브 워커와 매니페스트가 결정합니다.
현재 범위 리비전은 [지원 범위](coverage.md), 코어·워커 조합 준비는 [설치 안내](install.md)를 확인합니다.
스크립트 검증에는 데이터베이스·CSQL 인터프리터·데몬을 사용하지 않습니다.

[경계 사전 조사](orchestration/script-boundaries-preflight.md)에 고정한 매뉴얼과 소스 근거가 있습니다.
한국어 매뉴얼과 고정한 배치 분기는 어휘 블록 안의 명령 접두사를 보호한다는 점에서 일치합니다.
매뉴얼은 앞 공백을 허용하지만 고정한 원시 배치 분기는 첫 글자를 검사합니다.
따라서 검사기는 들여쓰기 없는 좁은 범위를 유지합니다.
고정한 명령 파서는 인수 공백도 제거합니다.
이 소스 조사에 따라 필수 인수 앞과 완전한 명령 형식 뒤의 ASCII 공백·탭도 허용합니다. 추가 형식의 고정 소스와 매뉴얼 근거는 [명령 티켓](tickets/followup-csql-commands.md)에 있습니다.

기본·필수 네이티브/CLI·프레임 LSP·필수 네이티브 LSP 검사는 따로 실행합니다.

```sh
just test
just test-native-parser
just test-lsp
just test-lsp-native
```

필수 검사에서 네이티브 산출물이나 선택 LSP 의존성이 없으면 실패합니다.
기본 검사는 이 선택 전제조건 없이 실행할 수 있습니다.
