## Public interfaces and current behavior

`Validator(config=None)` accepts a trusted `WorkerConfig` or absent configuration.
`validate(text, profile, script_mode)` returns `ValidationResult`.
Callers close it explicitly or use a context manager.
Close can interrupt another thread's validation and prevents later worker creation.
A profile change closes the old worker before assigning its replacement.
Diagnostics preserve distinct values and stable original-source ordering.
The qualified native implementation supplies statement classification and status priority.
The CLI adds acquisition, path identity, formatting, and aggregate exit selection.

`resolve_config(document_path=None, *, cwd=None, config_path=None, profile=None, script_mode=None, schema_snapshot=...)`
returns frozen `ResolvedConfig(profile, script_mode, schema_snapshot)`.
Omitting the snapshot override inherits metadata. Explicit `None` clears it.
Each configuration file resolves its own relative snapshot paths.
Relative caller values use the working directory.
Only the nearest ancestor configuration participates. Distant ancestors do not fill its omitted fields.
Every participating configuration must be valid, even when a later value overrides a field.
Stdin and untitled documents discover from the working directory.

Project keys are exactly `profile`, `scriptMode`, and `schemaSnapshot`.
The CLI does not load snapshots for semantic checks.
Both accepted script modes currently use conservative worker coverage.
Procedures and shell/include constructs remain unsupported until separately qualified.
Statement spans can include leading trivia, including CRLF before the next SQL token.
The guide documents this behavior and the original code-point coordinate contract.
