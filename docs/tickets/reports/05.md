## Implementation decisions

The command starts pygls `start_io` only and accepts no arguments.
The optional dependency set pins pygls 2.1.1, lsprotocol 2025.0.0, attrs 25.4.0, cattrs 25.3.0, and typing-extensions 4.15.0.
Python 3.10 additionally pins exceptiongroup 1.3.1. The core and CLI keep zero mandatory Python runtime dependencies.

Initialization and editor settings use the `cubrid` object.
Only trusted settings can select absolute worker/runtime paths and bounded deadlines.
Project metadata continues through the shared resolver and cannot select executables or credentials.
Relative editor paths use the initialization root or process working directory.
Untitled documents explicitly override inherited script modes with SQL unless the editor supplies a mode.

Each validation job captures an immutable source string, document version, and resolved configuration.
Cancellation closes the owned Validator through the library's tested close semantics.
Cancelling an asyncio future alone does not provide the worker ownership guarantee.
Configuration epochs also prevent a cancelled or superseded schema command from applying late results.
Completion uses cached snapshots and performs no configuration or snapshot reads.

pygls otherwise drops typed deserialization errors without a response.
The protocol boundary returns invalid-parameter errors for malformed requests, including negative completion positions.
The bootstrap preserves lifecycle exit status because pygls catches SystemExit internally.
Normal shutdown/exit returns 0. Exit or EOF without shutdown returns 1.

Public-interface TDD failures preceded absent-server behavior, completion edits, diagnostics, configuration/snapshots, cancellation, exit status, and invalid trusted paths.
A final child fixture exposed misleading native CRLF-interior ranges before the adapter converted them to T1002.
Tests observe framed messages, installed commands, filesystem inputs, and explicitly trusted worker child processes.
No test mocks an internal Validator or completion function. Production code contains no test delay or fault setting.
