## Red-to-green findings and retained guards

Initial public protocol tests rejected the new query and DML examples as
unsupported, then passed after the bounded predicates were added. The reduction
inventory exposed keyword overlap beyond a plain allowlist: LEFT and RIGHT are
also reserved function introducers, SET can introduce `SET(subquery)`, and
MATCHED is a nonreserved keyword accepted as a generic function name in MERGE.
Public red tests observed these native valid results. An explicit structural
keyword-before-parenthesis list now denies all these function routes before
native calls; retained protocol/corpus cases prove the guards. Generic quoted
calls and comment-hidden calls also remain denied.

The same audit identified INSERT/MERGE parenthesized VALUES-query branches.
Their actions only allocate/link SELECT/list/value nodes; positive fixtures and
the trace retain those paths. DELETE's `pt_check_unique_names` is in
name_resolution.c but only compares existing parser name/spec strings; duplicate
aliases produce a verified local S1001 rejection. No catalog action was needed
to qualify a required family, and no known catalog/internal failure was relabeled
as an ordinary syntax error. Prior coverage identities correctly return the
existing U1001 unsupported classification; an unexpected parsed statement kind
returns T1002. The new identity regression was corrected to preserve that
existing contract rather than changing the adapter API/classification.

## Exact practical limits and next step

This qualifies bounded forms in each required family, not all constructs of
those native kinds. Functions, hints, recursive CTEs, CTE/table-alias column
lists, ORDER/GROUP/HAVING/LIMIT, set operations, temporal/real/prefixed literals,
casts/collations, serial expressions, host/session variables, DBLINK,
INSERT SET/default/duplicate-key, MERGE DELETE and other unlisted features remain
unsupported. Quoted identifiers are deliberately simple; embedded delimiter,
escape and dot spellings are unsupported. A target followed by INSERT columns
must be unqualified. SET-immediate tuple assignments are unsupported. The
complete reduction inventory is a conservative overapproximation; its context
exclusions and incomplete-prefix/error actions require the accompanying manual
audit. It is not an arbitrary-grammar or memory-safety proof.

Successful parser-stage checks do not establish relation/column existence,
types, privileges, CTE binding, assignment-target validity or affected rows.
Catalog-dependent semantics are outside offline syntax qualification. Exact
host/runtime/build pins remain mandatory. Existing size/deadline/response/error
bounds, cancellation and shutdown guarantees are preserved. Process separation
is not an OS sandbox; the trace qualifies its retained corpus only.
