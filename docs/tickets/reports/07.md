## Description-alias blocker and error handling

The source path is concrete:

1. Grammar 7213–7255 and 7796–7802 route DESCRIBE, DESC and EXPLAIN to class-description helpers.
2. `pt_make_query_show_columns`, parser_support.c:6995, constructs schema-query nodes and local DB_VALUE placeholders.
3. `pt_dbval_to_value`, parse_dbi.c:573, calls `db_value_clone` unconditionally and ignores its return.
4. `db_value_clone`, db_macro.c:1460, invokes `CHECK_CONNECT_ERROR` from db.h:79–90.
5. The CS library defaults to disconnected at db_macro.c:93. The check sets `ER_OBJ_NO_CONNECT`, defined as **-224** at error_code.h:298.

The retained rejected-candidate probe observed all four forms with one tree,
zero parser errors and no internal-error flag, but **nativeErrorId=-224**.
The strengthened classifier returned T1002 with no successful statement kind.
Subsequent SHOW TRACE and SELECT observations returned zero native error.
This probe preceded the final exclusion predicates and is explicitly labeled
rejected evidence. It does not qualify those forms.

No connection, selected database, current user or schema identity was fabricated.
Other catalog-dependent SHOW helpers remain excluded. The final worker cannot
reach the rejected helper through a SHOW or description statement.
The user accepted these exclusions on 2026-10-29. The revised ticket criterion
requires them to remain unsupported. This decision completes that revised scope
without qualifying the rejected forms. Their parser-only backend is a separate
roadmap task.

The worker now calls `er_clear` before each parser allocation and records
`er_errid` after parsing. Any nonzero error becomes T1002, including an error
outside the parser error list. The adapter requires an integer nativeErrorId
and rejects an error-bearing response presented as success. It never ignores -224.

The original 179 cases remain in the final corpus. Only two expectations change:
DROP TABLE now passes by itself and contributes PT_DROP in the existing mixed
syntax-error case. Every admitted observation from those prior cases reports
zero native error. Other old fixtures and expectations remain intact.

## Profile and private protocol changes

The profile/version name and public Python interfaces are unchanged.
The coverage revision changes from v2 to **bounded-query-dml-schema-engineer-v3**.
Older workers fail explicitly with U1001 unsupported. No fallback occurs.

The existing six supported kinds remain first. The appended kinds are:
PT_CREATE_ENTITY, PT_ALTER, PT_DROP, PT_CREATE_INDEX, PT_ALTER_INDEX,
PT_DROP_INDEX, PT_ALTER_SERIAL, PT_DROP_SERIAL, PT_EVALUATE, PT_UPDATE_STATS,
PT_SET_SYS_PARAMS, PT_QUERY_TRACE, PT_COMMIT_WORK, PT_ROLLBACK_WORK and PT_SAVEPOINT.
`PT_SELECT` covers the exact SHOW TRACE helper without granting other SHOW coverage.

Each private `nativeObservations` object adds required integer `nativeErrorId`.
A clean observation uses zero. Fake native responses must include that field.
Structured parse responses also require `syntaxSettingsUnchanged: true` after
actual checks. The adapter accepts only the exact boolean true value. Missing,
false, null and non-boolean markers produce T1002. Bare native failure responses
retain their existing code handling without requiring the parse marker.
The adapter does not expose either field in `ValidationResult`.

Actual syntax parameters, UTF-8 client charset and the parser charset flag are
checked before and after every request. Public tests parse SET strings requesting
changed quotes, escapes, pipes, tracing and collation. Subsequent requests retain
the qualified values. EVALUATE, settings and transaction syntax is never applied.
