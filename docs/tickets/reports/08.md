## Classification and recovery

The [Korean guide](../../scripts.md) and [English guide](../../scripts.en.md) define the public behavior.
`classify` performs no filesystem, process, network, or database operation.
It returns `sql`, `command`, and `unsupported` parts in source order.
`lexical_error` records an unterminated SQL lexical block without granting syntax acceptance.
The source string remains the only source of text. No normalization or replacement buffer participates in native checking.

Batch command recognition respects strings, block comments, and double/backtick/bracket identifiers.
Single-quoted strings account for doubled quotes and the profile's backslash escapes.
LF alone begins the next batch line. CRLF remains two code points.
The preflight's Korean manual and pinned dispatcher agree that lexical-block override belongs to interactive mode.
This checker models batch documents.

Only full `;help`, `;exit`, and `;autocommit on/off` forms qualify.
The source evidence is pinned `csql.c:1096-1136`, where command/argument scanning and suffix trimming use whitespace.
The initial subset admits ASCII spaces/tabs between autocommit and on/off and after the full forms.
It keeps column-one prefixes and full command names/arguments mandatory.
Although the manual permits leading blanks, pinned raw batch dispatch checks `line_read[0]` at `csql.c:947`.
Indented commands therefore remain unsupported.
SQL mode continues to check its original SQL document through NativeWorker.

The checker inspects text after accepted exit commands and never changes autocommit.
Availability initialization still checks the exact selected profile, trusted worker, manifest, runtime, and identity for empty, commands-only, and unsupported-only CSQL documents.
Input validity and byte limits run before classification.
Owned worker creation, close/cancellation behavior, and native response/error guards retain their original implementation.

An informational command can preserve a pending interpreter SQL buffer.
Splitting `SELECT\n;help\n1;` into separate parser calls would report false fragment syntax errors.
The classifier instead keeps the pending statement and everything after it unsupported through EOF.
The same rule covers parentheses and unsupported commands whose buffer effects are unknown.
Earlier fully terminated SQL still receives its own native check.

`CREATE [OR REPLACE] PROCEDURE/FUNCTION/PACKAGE`, `BEGIN`, and `DECLARE` start an opaque procedural region through EOF.
No inner semicolon exposes a successful standalone SELECT or other native statement.
The classifier deliberately does not recover after an apparent procedural END.
Unterminated lexical tokens inside procedural regions retain S1001 alongside U1002.
These conservative EOF recovery limits remain explicit supported behavior, not additional grammar qualification.
